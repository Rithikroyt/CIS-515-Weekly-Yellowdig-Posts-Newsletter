# Newsletter quality gap: reference issue vs. generated issue

Compared on 2026-11-01: the instructor's Week 2 issue (`reference-private/Week2Newsletter-professor.html`, git-ignored) and
the Week 2 issue generated by this project (`reference-private/CIS515-Week-2-Newsletter-current.pdf`, git-ignored).
This document describes structure only; it contains no student content.

## Design system (already matched)

Both use the same system, so the renderer keeps it: `#F2F2F2` canvas, 640px white body, padding 36/48/48px,
Georgia headlines (44px h1, 27px spotlight titles), Arial labels and body, ink `#1A1A1A`, muted `#555555`, body
`#3D3D3D`, maroon `#8C1D40`, 3px black section rules, 1px `#D4D4D4` / `#E5E5E5` separators, email-safe tables, inline
CSS, no scripts, one 620px breakpoint (masthead and two-column blocks stack, images go full width).

## Structural differences

| Area | Reference | Generated (before) |
|---|---|---|
| Preview text | Hidden dek before the body | Present |
| Masthead, week, date range | Yes | Yes |
| Headline | 5–8 words, names the week's tension | Long descriptive headline |
| Dek | 25–35 words, concrete | Present, generic |
| Hero image | One 544px image under the dek | None |
| Credibility line | "Built with n8n — drafted by AI, checked by code…" | Yes |
| Metric row | builds · comments · workflow files · images | builds · comments · workflow files (**0**, coverage unknown) · people posting |
| Introduction | ~110 words naming 3+ builds and the class-wide pattern | Generic, no named examples |
| Spotlights | **6**, each: label, title, byline with "pipeline read from the workflow file", screenshot (max 340px tall, linked), pipeline chips, italic control note, "What the test showed", "From the thread", italic "Worth borrowing", "Read …'s post →" | **1** short spotlight with a "Worth borrowing" line |
| Themes / From the discussion | Not separate sections; discussion lives inside spotlights | Separate sections |
| Every build | Grouped into 7 use-case categories with counts; each entry: linked name, italic title, one-sentence explanation, spotlight marker, red comment count | One flat list of names and titles |
| Most discussed / most generous | Two columns | Two columns |
| What to carry into Week N+1 | 3 titled lessons tied to named builds + 4 numbered actions | Generic takeaways |
| Footer | Provenance line | Provenance line |
| Mobile | Stacks at 620px | Stacks at 620px |
| PDF | n/a (HTML) | Text only; no images; spotlight blocks may split across pages |

## Root causes

1. No asset path: screenshots and workflow files never reach the run, so workflow files are reported as 0 and no
   images or file-based pipelines can appear.
2. The model chooses spotlights, and one malformed or failed response could leave a single spotlight.
3. The newsletter schema has no fields for test results, thread insight or next-week actions, and no build grouping.
4. Post links were disabled (`POST_URL_FORMAT_VERIFIED = false`, guessed `/post/` path). The reference uses
   `https://yellowdig.app/n/<network>/community/<communityId>?postId=<postId>` with the API's post ids.

## Changes made (see `docs/newsletter-generator.md`)

Private asset intake into an n8n Data Table, deterministic spotlight selection (4–6) with evidence-based fallbacks,
a build-categorizer stage, extended spotlight and closing fields, a renderer rebuilt to the reference section order,
embedded optimized screenshots and a hero, verified post links, and PDF page-break rules.
